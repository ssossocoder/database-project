## 자료 안내

- [proposal.md](01_proposal/proposal.md): LMS 제출 대상 문서. 필수 7개 항목, 데이터 설계와 개발 계획을 포함합니다.
- [presentation.md](01_proposal/presentation.md): 10분 발표 구성, 대본, 예상 질의응답과 리허설 체크리스트입니다.
- [data-validation.md](01_proposal/data-validation.md): API 활용신청과 실제 표본 검증을 위한 부록입니다.
- [ERD 이미지](docs/erd/proposal-erd.svg): 15개 테이블의 PK/FK 관계 초안입니다. 이미지에 생략한 주요 속성은 기획안 표를 따릅니다.
- [발표용 핵심 업무 관계](docs/erd/core-relationships.svg): 9개 핵심 테이블과 두 N:M 경로를 보여줍니다.
- [ERD Mermaid 원본](docs/erd/proposal-erd.mmd), [Graphviz 원본](docs/erd/proposal-erd.dot): 수정 가능한 관계도 원본입니다.
- [주요 SQL 초안](database/proposal-queries.sql): 예상 스키마에 대한 설명용 질의입니다. DB에서 실행한 결과가 아닙니다.
- [Next.js 서버 연동 준비](app/README.md): 인증키 설정·실제 호출 명령·모듈 사용 방법입니다.
- [실호출 검증 요약](docs/api/latest-validation.json): 조건·표본 건수·응답 필드와 연결 검사 결과입니다. 인증키와 원본 응답은 제외했습니다.

## 학기 전체 관리 구조

후속 단계가 시작되면 해당 폴더에 산출물을 누적합니다. 기존 단계의 문서는 보존하고, 설계 변경 이유와 피드백을 새 단계에 기록합니다.

```text
database-project/
├─ README.md
├─ 01_proposal/          # 현재 기획안·발표·검증 부록
├─ 02_refinement/        # 요구사항·화면·ERD 보완 예정
├─ 03_analysis-design/   # 최종 명세·정규화·SQL·성능 검증 예정
├─ 04_final/             # 최종 시연·회고 예정
├─ app/                  # 현재 서버 API 모듈, 향후 Next.js 앱
├─ database/             # 현재 SQL 초안, 향후 DDL·적재·샘플
└─ docs/                 # ERD·참고 자료
```

## 다음 검증 순서

1. 완료한 API 표본 검증을 바탕으로 전용면적의 원 공고 근거와 공고 주소의 법정동 매칭을 확인합니다.
2. CSV 초기 적재·거래 고유성·재수집 변경 규칙을 검증하고 15개 테이블 명세를 보완합니다.
3. Next.js 앱에서 PostgreSQL의 검색·상세·개인 기록 기능을 구현합니다. 화면 조회는 DB를 이용하고 외부 API 호출은 수집 작업에서 관리합니다.
4. 12개월 범위 수집·정정·실패 대응과 실제 SQL·실행계획·트랜잭션을 검증합니다.
5. 제출 자료를 검토한 뒤 GitHub에 업로드하고, 로그아웃 상태에서 파일 URL과 상대 링크·이미지를 확인합니다.
